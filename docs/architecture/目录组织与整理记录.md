# 目录组织与整理记录

整理日期：2026-10-21。适用版本：Mycecard v0.6.1。

本次统一了玩家与敌人的目录层级、定义脚本与资源实例的位置，以及美术素材的分类。游戏规则、数值、类名和场景入口保持原有含义。

## 1. 目录按领域组织，领域内部按职责细分

项目没有按四个架构层分别建立四个大文件夹。顶层先回答“这是什么业务”，模块内部再回答“这是定义、状态、界面还是实例”。

例如 `battle/` 同时包含战斗模型、控制器和视图，但它们各有明确子目录及调用边界。文件放在同一个领域下，不代表视图可以直接修改规则。

## 2. 三组容易混淆的概念

### combatants 与 characters

- `combatants/` 表示战斗单位：基础生命、原画、敌人行动模式，以及共用显示。
- `characters/` 表示玩家可选择的一套角色配置：引用哪个战斗角色、初始牌组是什么、奖励池有哪些卡。

目前战士配置引用 `combatants/players/data/player.tres`。这是组合关系，不是两套重复的玩家属性。

玩家和敌人的资源分别放进 `players/data/` 与 `enemies/data/`。公共定义与视图留在 `combatants/` 根部。玩家目前没有额外的定义字段，因此继续使用 CombatantDefinition，没有为目录对称增加空的 PlayerDefinition 类型。

### 定义脚本与资源实例

`*_definition.gd` 定义资源有哪些字段、怎样验证；`.tres` 保存某份具体内容。

```text
run/run_definition.gd                    定义一局冒险的配置类型
run/data/default_run.tres                默认冒险的具体配置

battle/encounters/encounter_definition.gd 定义战斗遭遇的配置类型
battle/encounters/data/ruin_guard_encounter.tres
                                        遗迹守卫遭遇的具体配置
```

**约定：领域的 `data/` 只放资源实例，定义脚本放在所属领域或专属子模块。** `tests/fixtures/` 保留独立的测试配置，不混入正式内容池。

### 战斗遭遇与不期而遇

- `battle/encounters/`：敌人与单场能量、抽牌、手牌上限等战斗配置。
- `run/encounter/`：不期而遇的故事、选项、候选、执行与页面。

两者都可能使用 encounter 这个英文词，但职责不同。查找时以 `battle` 与 `run` 的领域边界区分。

## 3. 迁移清单

共迁移 **112 个文件**，包含脚本的 `.uid` 和图片的 `.import` 伴随文件。其中 47 组图片与导入配置共 94 个文件；5 组定义脚本与 UID 共 10 个文件；其余为 1 份玩家资源和 7 份战斗遭遇资源。

| 整理前 | 整理后 | 原因 |
| --- | --- | --- |
| `combatants/data/player.tres` | `combatants/players/data/player.tres` | 玩家与敌人同级，根部不再以通用 data 隐含玩家 |
| `battle/data/deck_entry_definition.gd` | `cards/deck_entry_definition.gd` | 牌组条目描述卡牌与数量，属于卡牌内容配置 |
| `battle/data/encounter_definition.gd` | `battle/encounters/encounter_definition.gd` | 战斗遭遇成为明确子模块 |
| `battle/data/encounters/*.tres` | `battle/encounters/data/*.tres` | 类型与实例就近组织，data 只放实例 |
| `run/data/run_definition.gd` | `run/run_definition.gd` | 整局类型不混入实例目录 |
| `run/map/data/map_definition.gd` | `run/map/map_definition.gd` | 地图类型不混入实例目录 |
| `run/map/data/map_node_definition.gd` | `run/map/map_node_definition.gd` | 节点类型不混入实例目录 |
| `assets/images/*` | `assets/cards/*` | images 改为明确的卡牌用途分类 |
| `artworks/player.png`、`cave_crawler.png`、`ruin_guard.png` | `assets/combatants/` 中对应文件 | 战斗角色美术集中到 assets |
| `artworks/background.png`、`main_background.png`、`map_background.png` | `assets/backgrounds/` 中对应文件 | 保留原有背景，消除第二个顶层美术目录 |

脚本 UID 文件随脚本移动；图片导入配置随原图移动。静态场景引用、动态加载路径、测试夹具、数值实验脚本的当前来源清单与活动文档同步更新。卡牌、敌人和地图的稳定内容 ID 保持不变。

现有图片版本没有因为“不再直接引用”就删除：旧图、替代图和背景仍可能用于比较或后续编辑。这次清理的是目录组织，不是素材淘汰。

## 4. 删除的空目录

删除前逐项确认绝对路径位于项目根目录以内，并检查包括隐藏文件在内确实为空；未使用递归删除。

原有的 4 个空目录：

- `export_templates/`
- `feature_profiles/`
- `script_templates/`
- `text_editor_themes/`

迁移后产生的 5 个空目录：

- `combatants/data/`
- `battle/data/encounters/`
- `battle/data/`
- `assets/images/`
- `artworks/`

项目没有配置这四个原有空目录中的内容。删除项目内的 `export_templates/` 不影响用户环境中安装的 Godot 导出模板。没有清空 `.godot/`、发布输出、音频制作源、草案或数值模型。

## 5. 保持历史数据的含义

三个数值模型目录维持原位置和既有运行入口。冻结清单中的 36 份历史数据、报告、参数和图片不改写；历史数据里的旧来源路径与指纹继续描述当时输入，不替换成当前目录后冒充原始来源。

可执行实验脚本使用新路径，并在隔离副本中生成新的来源记录。它们仍通过 `tools/project.py experiment` 运行，不直接覆盖主树的历史结果。当前不期而遇地图与旧固定休整地图的实验条件继续分开解释。

## 6. 新文件应该放在哪里

| 新增或修改内容 | 存放位置 |
| --- | --- |
| 新卡牌资源、卡牌原画 | `cards/data/`、`assets/cards/` |
| 新敌人属性与行动实例 | `combatants/enemies/data/` |
| 新玩家的基础战斗属性 | `combatants/players/data/` |
| 新可选角色及其初始卡池 | `characters/data/` |
| 新战斗遭遇 | `battle/encounters/data/` |
| 新地图资源 | `run/map/data/` |
| 新不期而遇实例 | `run/encounter/data/` |
| 新藏品及专属图标 | `collections/data/`、`collections/icons/` |
| 多个页面共同使用的控件 | `ui/` 下相应子模块 |
| 战斗专属显示与反馈 | `battle/view/`、`battle/presentation/` |
| 界面背景、卡框、事件插画 | `assets/ui/` |
| 当前说明或架构记录 | `docs/current/`、`docs/architecture/` |
| 回归测试及登记 | `tests/`、`tools/checks.json` |

不为每个架构概念建立空目录；只有实际内容需要独立归属时才新建模块。一个图标仅服务于藏品时可就近放在 `collections/icons/`，没有必要为了“所有图片必须同处”破坏局部内聚。

## 7. 验证入口

新增 [content_directory_test.gd](../../tests/content_directory_test.gd)，并登记到统一测试入口。它检查领域 data 目录不含定义脚本、旧目录不再出现、默认资源图可以加载、玩家 UID 稳定，以及迁移后的美术 UID 能解析到新路径。

```powershell
python tools/project.py test --match '^content_directory_test[.]gd$'
python tools/project.py clean-check
python tools/project.py tool-test
python tools/project.py docs-check
```

干净源验证用于排除旧导入缓存掩盖失效路径；历史文件完整性沿用已有冻结清单。目录整理不改变场景布局或视听效果，界面相关回归检查继续覆盖原有行为。
