# 综合数值模型

通过实际战斗规则比较牌组、双方生命、抽牌、奖励、休整与藏品的影响。战斗由独立 BattleSession 执行，不加载战斗界面；自动策略为“意图贪心v1”，按可兑现伤害、所需格挡和短期辅助收益选择操作，不查看未来洗牌顺序。

本目录包含历史数值数据。固定休整、旧地图和九牌开局等条件与现版本冒险分开记录，归档结果不能直接当作现版本的平衡评估。

## 运行

在包含 project.godot 的项目根目录执行：

~~~powershell
python tools/project.py experiment --scenario combined
~~~

依次更新卡牌模型、敌人模型、实际战斗数据和综合报表。环境配置见[开发环境](../docs/current/environment.md)，Godot可通过 GODOT_BIN 或 --godot 指定。

实验先创建 .godot/experiments/<run>/source 副本。输出写在副本内的模型目录；experiment-manifest.json 保存实验条件、执行结果、输入清单和新增输出。归档数据及原SHA不会被覆盖，单独在工作树执行旧评估脚本会被保护入口拒绝。

其他实验分别运行：

~~~powershell
python tools/project.py experiment --scenario collections
python tools/project.py experiment --scenario enemy-validation
python tools/project.py experiment --scenario boss-validation
~~~

这些命令的观察条件不同，结果不能直接拼成同一组样本。普通敌人重新搜索参数使用独立的 enemy-calibration 场景，训练不自动应用数值到正式资源。

## 主模型条件

主参数记录每条件24个种子，从20261003开始；战斗最多观察60回合，每回合最多60次操作。评分由胜利70分、剩余生命30分组成，具体计算见模型说明。

- 单场基线、单卡加入效果和生命扫描针对哥布林战士、遗迹守卫，不表示7种敌人的逐卡完整实测。
- 生命扫描比较玩家35/50/65/80生命与Boss 40/75/99/120生命，共16格，分别观察基础6张和参考9张构筑。
- 基础牌组为3打击＋3防御；参考构筑增加永恒、战神祝福、上勾拳。
- 历史连续路线包含24条哥布林→休整→遗迹守卫参照，以及24条随机分支路线，a/b/c各8条。
- 随机路线使用 tests/fixtures/phase5_run.tres 与 phase5_map.tres：两种不同普通敌人→15血休整→随机Boss。初始9张牌，每场普通胜利领取一张，完整推进后以11张进入Boss。
- 路线在初始化时绑定敌人；跨场保存牌组、当前生命与最大生命。休整恢复被生命上限截断，每局只走一条支线。
- 主报告禁用藏品。藏品效果只在独立配对实验中比较，基础六牌诊断也与正式九牌开局区分。

固定预算理论表可读取7种敌人模型，并用足够高的玩家生命观察至击杀，窗口为100个敌人行动；它与主实际战斗60回合的限制不同。

## 独立样本范围

三种普通敌人的独立验证各1,000场，共3,000场，固定50/50生命和基础6张牌，不含开局选牌、武器、奖励、休整或藏品。约80%只是在冻结策略和这些条件下的设计目标。

Boss独立验证共3,072场：三种Boss分别比较满血基础6张、参考9张、随机合法9张，以及35/50生命随机9张；每条件256场。随机开局每种稀有度取第一候选，不搜索最优构筑。

藏品实验共768条配对路线、2,175场归档战斗，比较三种牌组、四组藏品条件，每条件64个种子。详细条件和历史结果见各子目录，不能将单场胜率直接解释为整局通关率。

## 来源与使用范围

报表生成器检查来源SHA、模型参数、样本数、牌组和生命账目。新增效果或来源不匹配时应重新生成相应实验数据，不手工改写旧JSON的指纹。副本复算使用现有规则及明确保留的实验条件，不保证与缺少源码快照的旧结果逐样本一致。

[绘制血量对照.py](./绘制血量对照.py)只从汇总数据生成图像，不参与评分；它需要可选 matplotlib 依赖和脚本配置的中文字体，只能在合法实验副本中执行，combined 命令不会自动绘图。

归档保护说明见[数值基线](../docs/current/numerical-baselines.md)。自动策略、有限样本与固定构筑都有局限，最终数值仍需结合实际试玩。
