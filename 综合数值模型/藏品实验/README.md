# 藏品路线实验

比较无藏品、赤铜獠牙、守誓盾徽、余烬圣杯对连续路线的影响。无藏品是实验控制组，不是正式开局提供的第四个选项。

实验继承[综合模型](../README.md)的意图贪心策略和 BattleSession 战斗规则，分别记录通关、Boss入场生命、胜利治疗与休整收益。

## 运行与输入输出

在包含 project.godot 的项目根目录执行：

~~~powershell
python tools/project.py experiment --scenario collections
~~~

工具先更新卡牌和敌人模型，再运行藏品路线与汇总。输入包括[评估参数](./评估参数.json)、[主战斗参数](../评估参数.json)、tests/fixtures/phase5_run.tres、牌组、藏品和敌人资源。

输出写在 .godot/experiments/<run>/source/综合数值模型/藏品实验：

| 文件 | 内容 |
| --- | --- |
| [原始藏品数据.json](./原始藏品数据.json) | 地图绑定、逐轮战斗、奖励和生命账目 |
| [藏品评估数据.json](./藏品评估数据.json) | 配对比较、样本和置信区间 |
| [三件藏品实测评估.md](./三件藏品实测评估.md) | 完整实验报告 |

[评估藏品.gd](./评估藏品.gd)执行四组配对；[生成藏品评估.py](./生成藏品评估.py)检查来源、配对一致性和生命守恒后生成报表。工作树中的归档JSON、报告及来源SHA保持不变，不能直接运行旧脚本覆盖它们。

## 归档条件

2026-10-04的归档包含三种牌组×四组藏品条件×64个种子，共768条路线、2,175场战斗，种子从73000000开始。

- 牌组为基础6张诊断、随机合法开局9张和参考9张；参考构筑为基础牌＋永恒、战神祝福、上勾拳。六牌诊断在合法构筑后替换，仅用于实验。
- 路线按a/b/c轮换，使用冻结地图：两种不同普通敌人→15血休整→随机Boss。初始及最大生命为50。
- 同一种子的四组保持相同的7个战斗绑定、路线、初始牌组和战斗/奖励种子。共同获胜的普通节点领取相同第一候选。
- 每场普通胜利增加一张奖励，九牌组完整推进后以11张进入Boss，六牌诊断组以8张进入Boss。
- 圣杯在普通胜利生命回写后、奖励前恢复生命，实际恢复被最大生命截断；Boss和失败不触发。治疗与休整分别记账。
- 来源SHA-256覆盖相关规则、资源、评估脚本和藏品配置。重新计算不选择新参数，也不重训策略。

## 历史结果

下表只描述上述归档条件，不能作为现版本随机事件路线的通关率。

| 随机合法九牌开局 | 无藏品 | 赤铜獠牙 | 守誓盾徽 | 余烬圣杯 |
| --- | ---: | ---: | ---: | ---: |
| 通关 | 44/64（68.8%） | 48/64（75.0%） | 53/64（82.8%） | 53/64（82.8%） |

圣杯组每路线平均实际回血9.69；共同到达Boss的58对样本中，入场生命平均净增6.14。参考武器构筑中，獠牙57/64、无藏品58/64，说明自动策略变化可能使个别条件的胜率下降。

主指标为通关、到达Boss、终局生命和共同到达Boss的入场生命差。回合统计包含失败样本，更多回合也可能只是到达了后续节点。

逐段额外伤害、实际抵伤、格挡溢出与保留、盾牌猛击配合未作单独归因；这里不以约80%作为藏品或整局目标。完整样本和区间见报告，历史数据边界见[数值基线](../../docs/current/numerical-baselines.md)。
