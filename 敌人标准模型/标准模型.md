# 敌人标准模型与估值规则

版本v0.4，2026-10-03。基础锚点为每敌人回合12伤害或10格挡。先建立行动预算，再分别考察生命、可选成长、起手与循环节奏；自动工具已经支持力量、对玩家虚弱与易伤。

## 1. 单位与基础公式

定义 **1 E = 一个标准敌人回合的行动价值 = 12伤害 = 10格挡**。

**A直接 = D/12＋B/10。**

D为该行动所有段的总攻击伤害，B为新增格挡。这个公式评价供给潜力，默认伤害没有超杀、格挡可使用，不先假定特定玩家有多少盾。

| 行动 | 价值E | 基准判断 |
| --- | ---: | --- |
| 造成12伤害 | 1.00 | 基础攻击锚点 |
| 获得10格挡 | 1.00 | 基础防御锚点 |
| 造成6伤害＋获得5格挡 | 1.00 | 分配同一回合预算 |
| 造成6伤害 | 0.50 | 半个标准回合供给 |
| 获得5格挡 | 0.50 | 半个标准回合供给 |
| 造成18伤害 | 1.50 | 超过单回合基础攻击 |
| 造成12伤害＋获得10格挡 | 2.00 | 两份预算，不能仍算1 |

与[卡牌标准模型](../卡牌标准模型/标准模型.md)对齐：卡牌1 U是6伤或5格挡，因此 **1 E = 2 U**。同一份伤害或格挡按双方标准计价时，敌人单位数是卡牌单位数的一半。

这是价值尺度转换，不意味着敌人实际花2点能量，也不意味着玩家只花2费就一定能抵挡12伤：基础防御每费5格挡，要获得至少12格挡需要三张防御。进攻和防御的实际支付、取整、手牌供给仍独立计算。

### 设计区间

| 类型 | 首行动目标 | 完整行动允许上限 |
| --- | ---: | ---: |
| 普通敌人 | 约0.7 E | 1.8 E |
| Boss | 1.3 E | 2.6 E |

上限限定敌人基础状态下的完整行动预算，包括该行动全部伤害与格挡，不是攻击、格挡分别都可达到该数值。纯攻击预算分别21.6伤、31.2伤，整数配置上限分别21伤、31伤；纯格挡上限分别18和26。约0.7 E的起手取8伤，即0.667 E（允许0.05 E的约数误差）。

这些上限允许高强度固定循环、阶段变化或可选成长，并不要求每种敌人都有强化机制，也不要求每轮接近上限。四到五轮强化后达到上限只是可能的设计示例。例如当前普通敌人8伤→12伤→8伤→12伤，属于合法固定循环。

玩家自身易伤、敌人被施加状态等外部条件另按真实战斗计算，不通过模型上限硬截断伤害。后续加入敌人自身增益或对玩家减益时，还需核对该机制在敌人自带条件下形成的完整压力。

**成长机制例外：狂怒蛮兵（ragebound_brute）每次行动先增加2力量再攻击，力量不设上限。该成长机制允许突破普通敌人1.8 E，不能在游戏中自动停止强化。** 参数中的该敌人上限填写null，并记录例外原因；其首行动较低与长期增长分别报告。其他敌人继续适用普通/Boss上限。

普通敌人的设计偏好为生命尽量不超过100。参数以100记录生命偏好，独立核对是否满足；这是生命与行为共同调参的约束偏好，不把100生命换成某个行动E，也不在游戏运行时强行截断生命。

## 2. 单次行动、循环与峰值

敌人固定循环含m次行动：

**循环总价值 = ΣAi；循环平均价值 = ΣAi/m。**

**基准差额 = 循环平均价值−1；相对基准 = 循环平均价值×100%。**

同时记录首行动、最高单次行动价值、最高攻击伤害、伤害段数、空攻击回合和行动顺序。Boss身份不改变同一个动作的价格；它可以通过更多生命、更高平均预算或特殊节奏体现区别。

例如：

- 当前实验哥布林战士：8伤→12伤，循环为0.667＋1=1.667 E，均值0.833。
- 当前实验遗迹守卫：13格挡→8伤×2→18伤，循环为1.3＋1.333＋1.5=4.133 E，均值1.378。

实验前两者循环均值分别0.583与0.767，历史记录保留在[实验前评估](./实验前敌人量化评估.md)。

均值相同的敌人不一定难度相同。“每回合6伤”与“先休息两回合，再18伤”均值都是0.5 E，但后者更依赖玩家能否在爆发前击杀或准备格挡。交换循环顺序会改变首轮压力，不能只看总量。

3回合、6回合、12回合固定窗口按行动实际顺序展开。暂不折现直接循环均值，否则“12伤每回合”的无限基准会被错误压低。未来折现只用于某次成长/状态动作的局部估价，不替代行动序列本身的总分。

有永久力量成长时，资源中的“循环”只是动作顺序重复，实际伤害不会回到首次数值。因此自动报告明确称第一循环均值，并逐轮展开后续循环；12行动峰值是观测窗口最高值，无封顶成长的长期峰值没有有限上界。

## 3. 攻击、多段、格挡与顺序

### 3.1 攻击伤害

当前实际单段攻击公式：

**D = floor[(基础伤害＋力量)×攻击者虚弱倍率×目标易伤倍率]。**

虚弱0.75，易伤1.5，倍率完成后取整。多段逐段计算。无力量与状态时，3伤×2和6伤×1均为0.5 E；力量+2时，前者变5×2=10，后者变8，价值分别0.833与0.667 E。

多段不自动获得“穿盾奖励”：当前格挡是累计抵消伤害，5格挡面对3×2最终损失1生命，与一次6伤相同。多段的差异来自力量、逐段取整以及以后真实加入的触发机制。

有效生命压力需再扣玩家实际格挡和超杀。基础动作表保留原伤害供给；参考结算另报告玩家实际失血。

### 3.2 敌人格挡

敌人在自己回合开始清理旧格挡，随后执行行动获得的新格挡。玩家已在这之前行动，所以新盾保护的是 **下一次玩家行动**。

每次生成盾的基础供给为B/10；实际防御价值为它最终吸收的伤害/10。没有被打到、敌人被其他方式击杀或下一敌人回合被清掉的余量不算兑现。

同一份格挡不重复计价。格挡型行动不一定是“空回合”，但确实不在该回合直接扣玩家生命；意图可见时，玩家可能利用这一轮集中输出。

### 3.3 效果顺序

先获得力量再攻击，本次攻击可以受益；先攻击再获得力量，当前已结算伤害不受益。先给玩家易伤再攻击与攻击后给易伤也不同。

按每份效果资源的顺序解析，不能从意图名称猜测动作效果，也不能把新增状态追溯到已完成的伤害。

## 4. 力量与状态的量化

这些规则已用于咒缚侍徒与狂怒蛮兵。动作资源按效果顺序解析，状态递减复现正式代码；未知效果仍拒绝评估。

### 4.1 力量成长

一次获得s力量，其未来价值是：

**V力量 = Σ(未来每段攻击因该力量增加的伤害×折现)/12。**

无倍率时，+2力量对未来3次单段攻击增加6伤，即0.5 E；对未来3次双段攻击增加12伤，即1 E。每段按真实顺序和状态计算，不能用“每回合攻击次数”替代总段数。

局部估价暂沿用卡牌模型未来折现0.85：下一敌人行动增量乘0.85，再下一次乘0.85²。是设计假设，不是存活概率实测。

成长后的完整序列直接按实际伤害算，不把成长动作的“未来价值”再额外加一次到已有加成的伤害上。

例如每敌人回合先获得2力量、再打8基础伤，前三次伤害为10、12、14，三行动均值1 E；前六次为10、12、14、16、18、20，均值1.25 E。这显示成长敌人需要同时评估短窗口与长窗口。

### 4.2 给玩家虚弱

玩家攻击减少，等价于敌人保住相应生命：

**V玩家虚弱 = Σ(玩家原攻击−虚弱后攻击)×折现/10。**

玩家一次12伤变9，敌人少受3伤，局部防御价值0.3 E；两次6伤各变4，共少受4，价值0.4 E。玩家本来不攻击或该层虚弱只覆盖防守回合，收益可为0。

这既可能延长敌人寿命，也可能让玩家选择别的行动。不能既把少受3伤算作一次防御收益，又在存活模拟已经采用减伤后的生命曲线上再重复增加生命。

### 4.3 给玩家易伤

**V玩家易伤 = Σ(敌人易伤后攻击−没有这次易伤的攻击)×折现/12。**

后续一次12伤变18，新增6伤，价值0.5 E；后续两个3伤分别变4，总增2伤，价值0.167 E。对已处于易伤的玩家追加层数，只评新增覆盖窗口，不再叠50%倍率。

当前状态递减在敌人行动后发生。敌人首次施加虚弱或易伤时跳过当轮递减，让玩家的下一回合或敌人的后续攻击有机会兑现；已有状态再次延长不刷新这个例外。因此必须按当前代码追踪覆盖回合，不能施加后马上扣成零。

当前咒缚侍徒采用两步交替：“9基础伤后虚弱1”与“先易伤1再11基础伤”。首次攻击9，随后虚弱跳过当轮递减，下一玩家回合基础打击6→4。第二敌人行动先施加易伤，本次11基础伤变floor(11×1.5)=16；行动后虚弱归0，易伤因首次施加仍为1。第三敌人行动的9基础伤因此变floor(9×1.5)=13，随后再施加虚弱，易伤归0。实际攻击9→16→13→16，玩家打击6／4交替，两种状态各自消退。

通用规则仍支持每轮刷新：若每轮给已经存在的同一状态追加1层，随后递减1层，就会维持覆盖而不额外叠倍率。但当前咒缚侍徒采用交替减益，不能把这个通用示例当作它的永久虚弱或易伤。

### 4.5 自动报告的直接值与参考压力

逐轮直接值为 **实际攻击供给/12＋本次新增格挡/10**，攻击已包含该时点力量、弱化及易伤并逐段取整。原始配置价格、首行动实际直接值、第一循环以及3/6/12窗口分开记录。

虚弱没有敌人直接伤害，却可能保护敌人生命，不能静默记零。为保持可核验，另定义 **参考压力E = 直接E＋下一参考玩家回合被虚弱减少的攻击/10**。当前参考是均衡方案的两次基础打击6＋6，虚弱时4＋4，减少4伤，对应0.4 E防御潜力。全力进攻与防御优先的真实结算分别以三段和一段打击处理。

每次敌人行动的虚弱潜力归给其后的下一玩家回合；固定窗口末尾的状态按该下一回合估潜力，不称作窗口内已经兑现的生命收益。实际参考玩家结算只统计真正执行过的玩家攻击：被提前击杀时尚未兑现的状态不计收益。该指标依赖明确的参考攻击选择，不是所有玩家打法的通用单价。

力量与易伤引起的伤害增量另存作解释，已经包含在实际攻击供给内，不能再加进参考压力。参考压力也不再作为额外生命加入存活模拟。自动目标核对同时显示起手直接值与状态压力：低基础攻击的状态敌人可以出现直接起手低于0.7而完整参考压力接近0.7，不因此虚称直接起手达标。

### 4.4 复合状态

基础模型先按无既有状态比较。已有力量、虚弱或易伤时，用“有该效果/没有该效果”的真实伤害差计算，不能把所有状态的固定单价简单相加。

例如敌人本已有高力量，施加玩家易伤的收益随攻击量提高；如果敌人下一轮仅防御，这轮覆盖没有直接增伤。未来对两种状态同时生效的情况，应按0.75×1.5一起乘完再取整。

## 5. 能力、治疗与特殊机制

| 机制 | 评估方式 |
| --- | --- |
| 保留格挡 | 只计额外保留下来且最终吸收伤害的独立格挡，除以10 |
| 回合开始效果 | 明确第一次触发在哪个敌人自身回合开始，再累计存活窗口内收益 |
| 敌人治疗 | 实际治疗量×暂定0.15 E/生命；满生命为0 |
| 阶段切换 | 分阶段列行动与生命条件，报告触发后的峰值与均值 |
| 行动概率 | 有真实选择概率时算加权均值，同时保留尾部爆发 |
| 免疫、反伤等 | 必须先定义规则与实际机会损失，不能凭名称定固定分 |

敌人治疗暂定0.15 E/生命，对应卡牌治疗0.30 U/生命；是借用的初始系数，不是基础估值锚点，也不是当前已有敌人设计。效果因延长存活而增加的出手次数应在完整模拟里体现，不能在“治疗收益”与“多活几回合收益”之间重复加总。

当前敌人行动不支持玩家专用的抽牌、回能、武器强化、直接失血、最大生命损失、禁抽和攻击牌回能。后续新机制需先确认并实现，再做量化，不套用玩家牌的效果菜单当作现成敌人能力。

## 6. 生命与战斗长度单独建模

模型不设统一标准生命，因此 **不把某个固定生命值定义为一个标准敌人，也不把生命直接加进每回合分数**。

需要同时记录：

1. 最大生命、实际有效格挡与治疗。
2. 玩家击杀需要的回合数。
3. 玩家先手下，敌人真正成功行动的次数。
4. 玩家实际生命损失。
5. 首轮、循环均值、爆发峰值与长线成长。

没有格挡/治疗时，固定玩家每回合造成P伤的简化击杀回合为ceil(敌人生命/P)。玩家先手且第k轮击杀，敌人最多行动k−1次。存在盾、状态或成长时按时序展开，不能直接套生命÷平均伤害。

完整难度不压缩为“生命×行动均值”的单个值；这会遗漏起手防守、玩家提前击杀、盾的清除和爆发。生命与行为预算是两个设计维度。

## 7. 三种参考玩家方案

| 玩家方案 | 每轮固定攻击 | 每轮格挡 | 基础牌预算 |
| --- | ---: | ---: | ---: |
| 防御优先 | 6 | 10 | 1费打击＋2费防御 |
| 攻防均衡 | 12 | 5 | 2费攻击＋1费防御 |
| 全力进攻 | 18 | 0 | 3费攻击 |

三种方案均是3能量基础预算，假设每轮能拿到所需牌；不模拟开局抽牌、实际牌组循环、武器、能力或藏品。玩家初始生命50，每轮旧格挡清理后使用对应方案。

参考顺序：玩家攻击先消耗敌人上一回合留下的盾 → 敌人死亡则结束 → 敌人自身回合开始清除剩余旧盾 → 依序执行敌人行动 → 玩家下一轮。多段伤害共用本轮剩余玩家格挡，不能每段重新获得一份盾。

每种敌人提供三组确定性结果和逐轮记录，目的是核对生命、护盾、状态与先手节奏的影响。两张打击明确为两段6伤，而不是一次12伤；虚弱时二者因取整结果不同。这些固定供给方案不代表实际胜率或真实牌组保证能执行的打法。

新增三种普通敌人的80%基础牌组胜率目标由[综合数值模型](../综合数值模型/README.md)中的正式战斗与洗牌样本校准。这里的三种固定打法只能解释行为差异，不能用“3组里赢了几组”声称胜率80%。最大生命与攻击循环需要一起调参，记录样本量、牌组构成、策略、初始生命和不同种子的实际胜率。

## 8. 后续敌人设计的评估步骤

先给每次行动定价，再计算首循环、两循环与峰值；设定生命后检查玩家先手的击杀窗口。成长、状态与特殊机制另列收益条件，明确哪些回合可能无法兑现。

普通敌人与Boss按首行动与允许上限的设计区间评估，狂怒蛮兵按成长机制例外处理。相同均值下，可通过高峰低谷、段数、状态覆盖与起手来形成区别，成长是可选机制。用途从实验地图的固定节点或随机节点实际使用的普通／Boss遭遇池识别；随机池中的敌人只是可出现，每局不必遇见全部资源。未进入实验地图的资源需要模型参数显式声明普通/Boss用途；若声明与节点或随机池用途冲突，工具报错，防止误分类。

待设计完成后，将预期压力与实际试玩记录对照：存活多久、完成了哪些动作、玩家真实失血、盾浪费多少。再校准生命、行动数值与循环顺序。
